## 1. 执行规则

1. 严格按阶段推进；当前阶段 Gate 未通过，不进入下一阶段。
2. 每次实施前记录工作区文件基线。本目录当前没有 Git 元数据，不以 `git diff` 作为唯一证据。
3. 新旧架构只在迁移期短暂共存。每批内容通过新路径、搜索、Demo 和窄屏验证后，立即删除该批旧文件，不保留旧链接或重定向。
4. 教学事实、依赖版本和框架行为先查当前官方资料；外部检索使用 Tavily，不凭记忆补齐。
5. 保留 Shiki、主题、设计 token、现有 Demo 和动画等有效资产，但调用方式必须适配新 schema 和稳定 ID。
6. 样式禁止 Grid 和 `gap`，使用 flex、正常文档流与 margin；所有新增方法上方写规范中文注释。
7. 测试保持最少：优先覆盖目录 interface、路由解析、进度持久化和跨框架 Demo 等高风险行为。
8. 每阶段至少运行 `npm run type-check`、`npm run lint`、`npm run format:check`；改动影响构建或懒加载时再运行 `npm run build`。
9. 不主动提交代码。
