# 前端框架学习站重构设计方案

> 版本：v1.1
> 日期：2026-07-29
> 状态：已冻结，作为产品范围、信息架构与技术设计的权威依据  
> 配套执行文档：`docs/重构实施计划.md`

## 1. 设计结论

本项目从“Vue 3 API 展示站”重构为可持续扩展的“前端框架与工程化学习站”。站点不按技术名平铺内容，而是先回答用户的学习目的，再进入生态与技术模块：

```text
Portal（首页）
  → Purpose（系统学习 / 技术参考 / 项目实战）
    → Ecosystem（Vue / React / 通用工程化）
      → Module（Vue 核心 / Router / Pinia 等）
        → Overview（课程路线或官方参考索引）
        → Collection（阶段、专题或项目）
          → Entry（课程、参考条目或项目章节）
```

三类内容共享目录、搜索、来源追踪和交互资产，但使用不同模板与学习逻辑。当前 31 篇 Vue 内容按批迁移；迁移一批、验收一批、删除一批旧内容，不建立永久双轨架构。

## 2. 范围与非目标

### 2.1 当前范围

- Vue 生态：Vue 核心、Vue Router、Pinia；Nuxt 只预留位置。
- React 生态：React 核心 SPA、React Router、状态管理、数据管理；Next.js 后续再评估。
- 通用工程化：TypeScript、Vite、测试、构建部署、性能与质量。
- 三条产品路线：系统学习、技术参考、项目实战。
- Vue 与 React 均采用 TypeScript-first，早期示例只使用基础类型和类型推导。
- 学习进度只存浏览器本地。

### 2.2 暂不建设

- 不单独教授 HTML、CSS、JavaScript；课程可列出这些前置要求，但不在本期补基础教程。
- 不做账号、云同步、积分、排行榜、评论和社区系统。
- 不做多版本文档切换；内容面向核验时的当前稳定版。
- 不在首轮骨架阶段引入在线 Playground、完整 3D 场景或 CMS。

## 3. 产品信息架构

### 3.1 顶层模块

| 模块 | 用户问题 | 默认入口内容 |
| --- | --- | --- |
| 系统学习 | “我应该从哪里开始，按什么顺序学？” | 分阶段课程、前置提醒、学习进度 |
| 技术参考 | “某个 API、语法或配置怎么用？” | 可搜索参考页、签名、规则、示例 |
| 项目实战 | “如何把知识组合成可交付项目？” | 项目目标、里程碑、任务和验收清单 |

顶栏固定展示这三个学习目的。用户进入目的页后选择生态；再通过持久 Tab 切换技术模块。模块默认进入独立总览，不跳过路线直接打开第一篇详情。模块名称必须具体，例如“Vue Router”，不使用含义模糊的“更多”。

### 3.2 生态与模块

| 生态 | 第一批模块 | 后续模块 |
| --- | --- | --- |
| Vue | Vue 核心、Vue Router、Pinia | Nuxt |
| React | React 核心 SPA、React Router、状态管理、数据管理 | Next.js |
| 通用工程化 | TypeScript、Vite、测试、构建部署、性能与质量 | 按真实需求扩展 |

React 的“状态管理”和“数据管理”先作为稳定分类，不在架构阶段绑定具体第三方库。进入 React 内容阶段时再依据当前官方资料、维护状态和教学价值确定首批库，避免目录被某个短生命周期包绑死。

### 3.3 路由与稳定标识

路由直接表达层级和内容类型：

```text
/learn/vue/core/basics/template-syntax
/reference/vue/core/reactivity/ref
/projects/vue/core/beginner/task-manager
```

对应条目使用不受标题和路径展示文字影响的稳定 ID：

```text
vue.core.learn.basics.template-syntax
vue.core.reference.reactivity.ref
react.core.learn.basics.jsx
```

约束：

- 路径段使用小写 kebab-case；稳定 ID 使用小写点分段。
- `purpose / ecosystem / module / collection / entry` 均来自目录清单，不从任意 URL 猜测。
- 标题调整不自动改稳定 ID；确需改路径时同步更新目录与站内链接。
- 旧地址 `/vue3/:category/:id` 不保留映射、重定向或旧渲染器兼容层。

## 4. 新手学习路线

### 4.1 编排规则

- 主线按“认识概念 → 最小示例 → 常见任务 → 组合使用 → 原理与边界”递进。
- 课程分基础、中级、高级，但不以难度标签替代真实前置关系。
- 推荐顺序由显式 track manifest 管理，不依赖文件名、目录遍历顺序或全局 `docOrder`。
- 用户可以自由跳转。未满足前置条件时显示短提示和跳转入口，不锁定页面。
- 每课开头说明“学完能做什么”，结尾提供练习、下一课和相关参考。
- 高级概念可在基础课中以“稍后会学到”点到为止，不提前展开内部细节。

### 4.2 Vue 主线

Vue 核心以 Composition API + `<script setup>` 为唯一主讲路线：

1. 基础：SFC、模板语法、响应式状态、计算属性、事件与表单、组件、Props/Emits。
2. 中级：生命周期、模板引用、插槽与 Attributes、`v-model`、依赖注入、组合式函数、内置组件。
3. 高级：响应式进阶、异步与错误处理、自定义指令、渲染函数、性能与 SSR 边界。
4. 生态模块：在 Vue 核心基本组件能力之后进入 Vue Router，再进入 Pinia。

选项式 API 不进入新手主线，但在技术参考中完整可检索，并在相关页面提供组合式写法对照。

### 4.3 React 主线

1. 基础：JSX、组件、Props、State、事件、条件与列表、表单、组件组合。
2. 中级：Effect、Ref、Reducer、Context、自定义 Hook、路由与异步数据。
3. 高级：状态建模、并发体验、性能、错误边界、可复用组合模式。
4. 生态模块：React Router、客户端状态管理、服务端数据管理。

React 示例同样默认 TypeScript；不在课程中插入一套独立 JavaScript 基础课。

### 4.4 通用工程化路线

TypeScript 从类型推导和组件 Props 开始，再进入泛型、类型收窄和工程配置；Vite 从开发服务器与环境变量开始，再进入插件、构建和性能。测试、部署和质量内容应围绕 Vue/React 的真实项目展开，避免只讲孤立命令。

## 5. 内容模型与模板

### 5.1 共同元数据

所有条目共享最小元数据，目录和搜索只预加载这些字段：

```ts
interface ContentMeta {
  id: string
  type: 'lesson' | 'reference' | 'project'
  title: string
  summary: string
  ecosystem: string
  module: string
  collection: string
  level?: 'beginner' | 'intermediate' | 'advanced'
  prerequisites?: string[]
  related?: string[]
  tags: string[]
  sources: { title: string; url: string }[]
  appliesTo: string
  verifiedAt: string
}
```

`sources`、`appliesTo`、`verifiedAt` 是教学真实性字段，不允许由页面组件补默认值。课程顺序、预计时长和项目里程碑属于各模板的专有字段，不塞入共同元数据。

### 5.2 三类模板

| 模板 | 左侧 | 中间正文 | 右侧 |
| --- | --- | --- | --- |
| 课程 `lesson` | 当前学习路径与阶段 | 目标、讲解、示例、易错使用提示、练习、总结 | 本页大纲、相关参考 |
| 参考 `reference` | 当前模块的分类/API 列表 | 摘要、签名、参数、行为、示例、易错使用提示 | 本页大纲、版本与来源 |
| 项目 `project` | 里程碑与任务树 | 项目说明、实现步骤、阶段产物 | 验收清单、相关课程 |

模板定义信息顺序和导航行为，内容块只负责正文表达。不能通过给一个通用页面不断增加布尔属性来模拟三种页面。

### 5.3 内容块

保留现有 `heading`、`text`、`code`、`demo`、`tip`、`principle`、`table`，补充确有跨内容复用价值的 `steps`、`exercise`、`checklist`、`compare` 和 `pitfalls`。定制交互统一使用 `interactive` 逃生块，并要求完整限定 ID。

同一内容块由三类模板共用；模板专有的页头、进度、里程碑和验收区域不伪装成正文块。代码演示继续遵守“运行源码与展示源码同源”：组件真实运行，源码通过 `?raw` 展示。

### 5.4 易错使用提示

每篇课程知识点和参考条目必须包含一个“易错使用提示”小节，紧跟结构化 `pitfalls` 块：

```ts
{ type: 'heading', content: '易错使用提示' },
{
  type: 'pitfalls',
  items: [{
    title: '不要直接解构 reactive 的基本类型属性',
    description: '解构只在当下读取一次代理属性，得到的是普通值。',
    consequence: '局部值与源对象断开连接，后续更新不再同步。',
    wrong: { lang: 'ts', content: 'const { count } = state' },
    correct: { lang: 'ts', content: 'const { count } = toRefs(state)' },
  }],
}
```

编写前使用 Tavily 检索该 API 或知识点的常见误用，优先核对官方 API、指南、规范、源码、变更记录和官方 issue；社区文章只作为发现线索，不能单独支撑结论。每篇以约五个对新手最有价值的常见问题为目标，最多不超过十个；一手资料不足时可以少于五个，不得为凑数编造或拆分重复问题。每点必须分别写明原因、可观察后果、错误示范和正确示范，不写“注意使用”“谨慎操作”一类空泛提醒。

核验依据加入条目的 `sources` 和文件头查证记录；版本相关行为同步更新 `appliesTo` 与 `verifiedAt`。“易错使用提示”还要加入参考条目的 `anchors`，确保能从页面大纲直接定位。

### 5.5 Vue API 覆盖策略

长期目标是让 Vue 官网 API 索引中的主题全部可搜索和定位，但不把 206 个索引条目机械拆成 206 篇长文：

1. **核心详解**：响应式、组件通信、生命周期等高频能力，提供签名、心智模型、Demo 和必要的原理动画。
2. **主题合并**：指令、应用配置、选项式 API、SFC 能力等按官方主题组织，页内锚点覆盖具体条目。
3. **速查条目**：SSR、自定义渲染、编译标志等低频或环境相关能力，提供准确边界、链接和最小示例。

覆盖矩阵记录每个官方条目对应的站内路由、深度、版本和核验日期。`src/content/catalog/manifests/vue-core-reference-index.ts` 是页面的结构化数据源，`docs/vue-官方内容覆盖矩阵.md` 保留官方范围、版本提示与覆盖统计。

## 6. 软件架构

### 6.1 `LearningCatalog` 深模块

目录、路由、搜索、侧栏和上一篇/下一篇不再分别理解文件路径。它们只依赖 `LearningCatalog` 的小接口：

```ts
interface LearningCatalog {
  getNavigation(scope: CatalogScope): CatalogNavigation
  getLearningTrack(scope: LearningTrackScope): LearningTrack | undefined
  getReferenceOverview(scope: LearningTrackScope): ReferenceOverview | undefined
  getEntry(id: string): ContentMeta | undefined
  loadEntry(id: string): Promise<ContentEntry>
  search(query: string, scope?: CatalogScope): SearchHit[]
  getNeighbors(id: string): EntryNeighbors
}
```

模块内部负责清单校验、排序、路径生成、索引和懒加载。调用方不读取 `import.meta.glob`、文件路径或 track manifest。测试通过这一 interface 验证行为，不暴露仅为测试服务的外部 Adapter。

### 6.2 元数据与正文加载

条目文件导出轻量 `meta` 和正文。构建时使用命名导入收集 `meta`，正文保持动态导入：

```ts
export const meta = defineReferenceMeta({ /* 轻量字段 */ })
export default defineReference({ /* blocks */ })
```

目标是进入首页、生态页或打开搜索时不执行全部正文模块。构建验收必须查看产物或网络请求，确认正文按路由拆分，不能只凭代码形式判断已懒加载。

### 6.3 Demo 与原理动画

当前按 basename 查找组件的方式会在多生态下冲突。新内容统一使用完整限定 ID，例如：

```text
vue.core.reference.reactivity.ref.basic-counter
react.core.learn.basics.state.counter
```

交互宿主暴露统一的“加载组件 + 加载源码”interface。Vue 和 React 内容同时存在后，Vue Demo Adapter 与 React Demo Adapter 是两个真实实现：Vue 组件直接渲染；React Adapter 负责挂载和卸载 React root。两者都继续从同一个源文件读取运行内容和 `?raw` 源码。

### 6.4 搜索

- 第一阶段索引标题、摘要、标签和页内 API 锚点，不加载正文全文。
- 默认限制在当前目的/生态内，并允许扩展到全站。
- 结果项直接携带稳定 ID 和目标路径，点击项本身，不读取悬浮时遗留的 `selected`。
- 搜索弹层必须有焦点锁定、`Esc` 关闭、关闭后焦点恢复、正确的 dialog 语义和触屏行为。

### 6.5 本地进度

第一版只实现一个版本化 localStorage 模块，保存已完成条目、最近访问位置和 track 进度。当前只有一种存储实现，不提前创建云同步 seam 或 Adapter。数据损坏时允许回到空进度，不影响内容浏览。

## 8. 页面与响应式布局

### 8.1 首页

首页是单屏沉浸式选择器，而不是长滚动营销页。第一屏明确展示三个顶层目的；选中后在同一空间中展开 Vue、React、通用工程化入口。桌面采用 2.5D 材质舞台，窄屏允许自然纵向滚动，不能为了“单屏”压缩文字或隐藏入口。

### 8.2 模块总览

生态下的持久 Tab 切换核心、路由、状态等模块。课程总览按基础、中级、高级展示知识类别卡片；已上线类别整卡进入首课，纯规划类别不可点击。参考总览保留官方六大分类和二级标题，支持页内筛选并隐藏空分组。两类总览都是无左右侧栏的独立页面。

### 8.3 内容页

- 宽屏：左侧导航、中间正文、右侧上下文区域。
- 中等宽度：右侧区域收起到页内按钮，左侧保持可折叠。
- 窄屏：正文单列；左侧变为从触发按钮原点出现的抽屉；右侧信息合并到正文页头或底部。
- 布局只使用 flex、正常文档流和 margin，禁止 CSS Grid 与 `gap`。
- 左侧第一项固定返回当前模块总览；站内关联学习放在正文末尾，官方来源桌面放右栏、移动端放正文末尾。

## 9. 视觉与动效系统

### 9.1 两档动效强度

- **首页与生态选择**：允许明显的空间层级、材质变化、卡片聚焦、视差和连续转场，负责制造期待感。
- **课程、参考与项目正文**：保持安静，只使用导航反馈、内容进入、展开收起、进度完成等有解释作用的动效。

华丽不等于持续晃动。大面积循环背景、与操作无关的弹跳和同时竞争注意力的动画均不采用。

### 9.2 Apple 式原则

- 顶栏、抽屉、弹层使用分层毛玻璃；避免浅色玻璃叠浅色玻璃。
- 指针按下立即反馈；可交互转场从当前屏幕值继续，允许中途反向。
- 普通 UI 默认临界阻尼、无弹跳；只有拖拽或甩动继承速度时才允许少量回弹。
- 进入与退出沿同一路径，弹层从触发源附近出现。
- 优先动画 `transform` 与 `opacity`；材质出现时可同步变化 scale、opacity 和 blur。
- 大标题使用紧凑行高和轻微负字距，正文使用系统字体与舒适行高。

最终首页先做可交互原型，再确定原生 Web Animations、轻量 spring 工具或第三方动画库。没有可验证收益不增加运行时依赖，也不以完整 WebGL 场景为主体。

### 9.3 动效降级

- `prefers-reduced-motion: reduce`：空间位移、弹簧和视差改为短交叉淡化或静态切换。
- `prefers-reduced-transparency: reduce`：玻璃改为高不透明度实体表面。
- `prefers-contrast: more`：提高表面不透明度和边界对比。
- 动画期间不锁定输入，不因动画阻止导航。

## 10. 可访问性与性能

### 10.1 可访问性

- 每页使用明确的 `header / nav / main / aside`，提供跳到正文入口。
- 所有功能可由键盘完成；焦点样式不能被视觉效果吞掉。
- 弹层锁定焦点、支持 `Esc`、关闭后恢复触发元素焦点。
- 控件至少满足舒适触摸面积；图标按钮有可读名称。
- 颜色不是状态的唯一表达，亮暗主题均保证正文、代码和玻璃表面的可读性。

### 10.2 性能

- 首页与目录不得预加载全部正文、Demo、Shiki 语言或 React 运行时。
- React 依赖只在进入 React Demo 或对应内容时加载。
- 2.5D 首页以合成层属性为主，避免在指针移动时触发布局。
- 每个阶段记录关键路由的资源请求和体验基线；最终以真实构建产物复验，而不是只看开发模式。

## 11. 内容真实性与版本治理

- 教学事实优先查官方文档和官方仓库；外部检索使用 Tavily，不能用模型记忆补齐签名或版本。
- 每个条目记录来源 URL、适用版本和核验日期；演示的内部机制也必须有来源。
- 内容面向当前稳定版。版本变化通过更新条目和覆盖矩阵处理，不建设多版本切换器。

## 12. 迁移与删除策略

### 12.1 可保留资产

继续使用 Vue、Vue Router、Pinia、Vite、Shiki、主题 store、设计 token、CodeBlock、Demo、原理动画和 `?raw` 同源展示。保留的是能力与内容，不是旧注册表、旧路径假设或 basename 查找方式。

### 12.2 迁移顺序

1. 先建立新 schema、目录、路由和三类模板骨架。
2. 首个垂直切片迁移“技术参考 → Vue → Vue 核心 → 响应式 API”。
3. 按 `computed-watch → composition → component-communication → builtin-components → global-api → advanced` 迁移其余旧内容。
4. 每批验证新路径、Demo 源码同源和搜索后，删除该批旧数据与旧 Demo，不保留旧链接。
5. 全部旧内容迁移完再删除旧 `ApiDoc` 类型、registry、页面和过期注释。
