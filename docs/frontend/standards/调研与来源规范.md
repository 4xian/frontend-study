# 调研与来源规范

> 版本：v1.0  
> 状态：生效

## 1. 调研生命周期

每个新模块先建立 R0 临时调研文件，位置为 `docs/frontend/plans/<module>/`。R0 冻结以下内容：

- 当前稳定版本、官方入口和固定源码。
- 课程范围、顺序、前置关系和学习终点。
- 官方 Reference 索引、稳定分母和观察/受限范围。
- 每批 entry、Demo 或 fixture、focused tests、浏览器路径和停止边界。
- 不进入本模块的内容和延期决策。

调研可以预先一个批次进行，但当前批次 Gate 未关闭前不得发布下一批正文。模块 Gate 关闭后，把长期
规则写入规范、最终统计写入 `coverage-matrices/`、状态写入总计划，然后删除该模块全部调研与实施计划，不保留
archive 或旧链接。

## 2. 来源优先级

1. 规范、标准和官方 Reference。
2. 精确版本的官方 Guide、API、类型声明和发布说明。
3. 固定 tag/commit 的官方源码与官方测试。
4. 官方 issue、RFC 或维护者解释，用于版本问题和设计动机。
5. 社区文章、问答和搜索结果，只用于发现候选问题。

外部搜索统一使用 Tavily，并尽量限制官方域名。搜索摘要、AI 输出和社区文章不能单独支撑课程事实。
没有可靠来源时停止写入该结论，不得猜测或用“通常如此”掩盖不确定性。

## 3. 结论与证据

| 结论 | 最低证据 |
| --- | --- |
| 语法、类型和签名 | 官方 Reference 或规范 |
| 默认值、生命周期和错误行为 | 精确版本官方文档，必要时源码/测试 |
| 新增、废弃和迁移 | 官方发布说明或迁移指南 |
| 内部机制 | 固定源码与官方测试，并标明非公共合同 |
| 常见错误 | 官方 warning/限制或可重复最小复现 |
| 性能结论 | 明确环境下的构建产物、trace 或基准 |
| 工程建议 | 官方建议或可解释的项目证据，并写明取舍 |

条目的 `sources` 只收录实际支撑正文的来源，不能为了显得充分而堆链接。`appliesTo` 与
`verifiedAt` 必须和本批调查一致。

## 4. 易错点研究

使用 Tavily 搜索官方文档、官方 issue 和高频社区问题，先收集候选，再回到一手来源或最小复现确认。
每点回答：

```text
错误名称 -> 触发条件 -> 原因 -> 后果 -> 错误示例 -> 正确示例 -> 适用版本 -> 来源
```

优先保留对新手影响大、后果可观察且容易真实发生的问题。数量通常约五个，最多十个；找不到足够
高质量问题时减少数量。

## 5. 源码推导

每条推导使用三段式：

1. **官方事实**：固定版本源码或测试实际做了什么。
2. **课程推导**：由事实可以合理得到的使用方式或选择建议。
3. **边界**：该推导不承诺什么，哪些版本或环境需要重新核对。

推导用于解释适用场景、高级用法和设计取舍，不能发明新的公共行为。语言级主题没有可读运行时源码
时，改用规范和编译器可复现行为完成同样结构。
