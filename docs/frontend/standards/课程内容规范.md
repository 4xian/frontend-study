# 课程内容规范

> 版本：v1.0  
> 状态：生效  
> 适用范围：`src/content/entries/learn/<ecosystem>/<module>/`

## 1. 课程职责

课程负责建立心智模型、学习顺序和可完成练习，不承担完整官方索引速查。每课只解决一个主要学习
目标；关联的高级能力可以短暂预告并链接后续课程，不能在基础课提前展开整套实现细节。

课程按基础、中级、高级组织，但真实顺序由前置关系和 track manifest 决定。每个模块必须先有独立
总览，类别卡片进入该类别第一课；类别本身不是内容条目。

## 2. 文件与元数据

```text
src/content/entries/learn/<ecosystem>/<module>/<collection>/<topic>.ts
src/content/demos/<ecosystem>/<module>/<collection>/<topic>.vue|tsx
```

课程必须通过 `defineLessonMeta()` 和 `defineLesson()` 定义。以下字段不可缺少：

| 字段 | 规则 |
| --- | --- |
| `id` | 全局稳定，必须与 manifest 一致 |
| `title` | 具体知识点名称，不使用“第一章”等顺序词 |
| `summary` | 一句话说明学完能解决什么问题 |
| `ecosystem/module/collection` | 与目录和路由一致 |
| `level` | `beginner`、`intermediate` 或 `advanced` |
| `prerequisites` | 真实前置课程 ID；没有时为空数组 |
| `related` | 已上线的相关课程和 Reference ID |
| `tags` | 稳定检索词，不堆叠无意义同义词 |
| `sources` | 实际支持正文结论的一手来源 |
| `appliesTo` | 精确适用版本或版本范围 |
| `verifiedAt` | 本批真实核验日期 |
| `estimatedMinutes` | 与内容和练习规模相符的估算 |

## 3. 固定内容顺序

课程按以下节奏编写：

1. 学完能做什么：`objectives` 提供可验证目标。
2. 为什么需要：用学习者已经理解的场景引出问题。
3. 核心概念：最小模型、语法或 interface。
4. 分步使用：从最小示例逐渐组合，不一次堆出最终代码。
5. Demo 或编译 fixture：只验证本课关键行为。
6. 易错使用提示：结构化 `pitfalls`，紧跟同名 heading。
7. 源码推导与适用场景：区分官方事实、课程推导、适合与不适合使用的条件。
8. 练习：要求学习者做出修改、预测结果或解释原因。
9. 总结：`recap` 只保留可带走的判断规则。
10. 下一课与相关 Reference：链接必须真实可用。

章节可以按主题增加，但不能删掉目标、易错提示、推导/场景、练习和总结。纯编译期主题可以使用
编译 fixture 代替浏览器 Demo；没有可观察价值时不得为了形式强行创建动画。

## 4. 易错提示与推导

每个易错点包含 `title`、`description`、`consequence`、`wrong` 和 `correct`。通常选择约五个高价值
错误，最多十个；不得把同一个问题拆成多个条目凑数。错误示例必须能够触发所述问题，正确示例只
修复当前问题，不夹带无关架构重写。

“源码推导与适用场景”使用有序条目。每项先写固定版本源码或官方测试证明的事实，再写课程层面的
推导和使用边界；不得把内部实现描述成公共承诺。没有源码价值的语言规则可以改为“原理与适用
场景”，但仍需绑定规范或官方编译行为。

## 5. 可复制骨架

```ts
/**
 * 查证日期：YYYY-MM-DD
 * 查证来源：官方文档、固定版本源码与官方测试
 */
import { defineLesson, defineLessonMeta } from '@/content/schema'

export const meta = defineLessonMeta({
  id: 'engineering.typescript.learn.basics.example-topic',
  type: 'lesson',
  title: '具体知识点',
  summary: '说明学完能够解决的问题',
  ecosystem: 'engineering',
  module: 'typescript',
  collection: 'basics',
  level: 'beginner',
  prerequisites: [],
  related: [],
  tags: ['TypeScript'],
  sources: [{ title: '官方来源', url: 'https://example.com' }],
  appliesTo: 'TypeScript x.y',
  verifiedAt: 'YYYY-MM-DD',
  estimatedMinutes: 30,
})

export default defineLesson({
  meta,
  objectives: ['完成后能够验证的目标'],
  blocks: [
    { type: 'heading', content: '为什么需要' },
    { type: 'text', content: '从具体问题引入。' },
    { type: 'heading', content: '核心概念' },
    { type: 'text', content: '解释最小心智模型。' },
    { type: 'heading', content: '易错使用提示' },
    {
      type: 'pitfalls',
      items: [
        {
          title: '明确的错误名称',
          description: '解释错误原因。',
          consequence: '说明可观察后果。',
          wrong: { lang: 'ts', content: '// 错误示例' },
          correct: { lang: 'ts', content: '// 正确示例' },
        },
      ],
    },
    { type: 'heading', content: '源码推导与适用场景' },
    {
      type: 'steps',
      items: [{ title: '事实与推导', content: '官方事实；课程推导；适用边界。' }],
    },
    {
      type: 'exercise',
      title: '练习目标',
      instructions: '要求学习者执行一个可验证动作。',
    },
  ],
  exercises: ['完成并解释练习结果'],
  recap: ['一条可复用判断规则'],
})
```

## 6. 发布检查

- manifest 中的前置、顺序和状态与正文一致。
- 目标、总结、易错点和推导章节满足 schema 与模板测试。
- Demo/fixture 与课程内容同批完成，不发布半成品课程。
- 桌面和 390px 可完成阅读、目录切换、练习与相关跳转。
- 切换课程后正文回到顶部，左侧学习路径不重复创建或丢失滚动位置。
