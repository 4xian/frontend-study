# 质量门禁规范

> 版本：v2.1
> 日期：2026-08-19
> 状态：生效

## 1. 批次流程

每批严格执行：

```text
冻结范围 -> 官方调研 -> manifest/临时反馈环红灯 -> 正文与 Demo -> 同一反馈环转绿
-> 范围内质量命令 -> 代表性浏览器验证 -> 按风险复审 -> 勾选本课 -> 停止
```

当前批次未完成全部流程时，不开始下一批，也不预先调研下一课。每条完成声明必须对应当前工作区和
当前文件快照，不能复用旧 Gate 证据。

## 2. 临时验证资产

仓库保留根目录 Vitest/Playwright 配置、依赖和脚本，并预留空的 `tests/unit/`、`tests/e2e/` 目录；不保留
`*.spec.*`、`*.test.*` 或 fixture。需要自动化反馈环时，使用 `mktemp -d` 在 `/tmp` 创建最少的一次性
验证资产，只覆盖高风险 interface：

- track：ID 唯一、前置存在、顺序无环、available 状态原子更新。
- Reference index：官方冻结集合、计数、target entry 和唯一 anchor。
- Markdown template：frontmatter、目标、总结、签名、结构化易错点、来源和必要 heading。
- Demo manifest：完整 ID、组件/源码同源、跨 Technology 不串、外部 URL 合法。
- 高风险 Demo：一个 focused 行为检查，不为每段说明重复建立验证。

类型或构建行为优先使用位于临时目录的真实编译/build fixture；浏览器自动化只验证用户可观察的导航
和交互。验证结束必须删除临时目录，并确认仓库内没有新增测试资产、验证报告或截图证据。

## 3. 质量命令

根据改动范围运行：

```sh
npm run type-check
npm run test:unit
npm run test:e2e
npm run lint
npm run format:check
npm run build
git diff --check
```

文档批次至少运行针对目标文档的 Prettier 检查和链接/旧引用检索。存在与本批无关的 dirty 或
untracked 文件时，先记录基线，只运行触及范围 lint/format；不得格式化、删除或暂存他人资产来制造
全仓绿灯。构建只在代码、配置、懒加载或产物契约受影响时运行。

## 4. 浏览器验证

复用已有本地服务，不启动重复实例。每个内容批次只抽取一个代表课程、一个代表 Reference 和受影响
Demo 路径，覆盖：

- 桌面与 390px。
- 键盘、焦点、触摸和 reduced motion。
- 200% 文本、无横向溢出、无内容遮挡。
- 详情切换正文回顶，左右导航保持独立滚动。
- 目标 anchor、相关链接、官方来源、console 和资源请求。
- 已切换 Module 的新路径可以刷新，旧 URL 未命中且没有 redirect。

编译期、SSR、HMR、代理、部署和性能能力必须使用匹配环境验证；未运行时明确标记
`Deferred/not-run`，不能用普通 SPA smoke 替代。

## 5. Gate 与复审

批次结束前分别复审：

- **Standards**：是否遵守仓库、内容、模板、来源和验证规范。
- **Spec**：是否完整实现本批冻结范围、计数、顺序和停止边界。

发现问题只修复被确认的问题，并复跑同一 Gate。复杂课程、Demo、manifest、进度或共享代码变更按仓库
规则复审；简单文字和格式修改只做定向验证。复审用于发现问题，不在仓库保存逐课审查结果、signoff、
closeout 或批次流水账。

课程完成状态只由所属模块课程计划中的复选框表示。全部适用验证通过后勾选本课；存在未解决问题时
保持未勾选。模块 Gate 关闭后可以在总路线和 `coverage-matrices/` 更新模块级状态，但不得向课程计划
追加逐课证据。

涉及目录、Catalog 或路由模型的结构变更必须额外验证稳定 ID、Reference 分母、Demo 行为、进度、
深链与零孤立引用，不能只凭局部类型检查关闭 Gate。

## 6. 工作区规则

开始前记录 `HEAD`、分支、`git status --short`、untracked 文件和目标文件范围。只修改批准范围，
不清理相邻代码，不回退他人改动，不执行 `git add`、commit、push 或 PR，除非用户明确授权。
