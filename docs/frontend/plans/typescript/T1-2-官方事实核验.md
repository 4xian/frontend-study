## 3. 冻结事实与边界

### 3.1 联合与字面量

1. `A | B` 表示值可以来自任一成员；未收窄时只能使用所有成员共有的操作。
2. string、number 和 boolean literal 可组成有限状态合同，避免把状态放宽成普通 primitive。
3. 每个 union 成员具有共同 literal 字段时，该字段可作为 discriminant。
4. `never` 可承接穷尽分支；新增未处理成员时，赋值给 `never` 应产生诊断。

### 3.2 类型收窄

1. TypeScript 根据可达性与控制流分析调整分支中的类型。
2. `typeof`、等值比较、truthiness、`in` 与 `instanceof` 都只在各自运行语义成立时提供证据。
3. `in` 检查的可选属性可能出现在 true 与 false 两侧，不能把它当成绝对互斥证据。
4. 用户定义 type predicate 的返回类型为 `parameter is Type`；实现仍必须执行真实运行检查。

### 3.3 type 与 interface

1. 两者都能描述对象形状；TypeScript 按结构而非声明名称判断普通对象兼容性。
2. type alias 还能命名 union、primitive 与 tuple；interface 只声明对象形状。
3. interface 可用 `extends` 扩展，也可由同名声明合并；type alias 不能被同名重开。
4. 选择依据是合同能力，不使用“interface 永远更高级”或“type 永远更现代”的口号。

### 3.4 模块

1. 含顶层 `import` 或 `export` 的文件是模块；没有这些声明的文件默认按 script 参与全局作用域。
2. 模块拥有自己的作用域，值和类型只有显式导出后才能由其他模块导入。
3. `import type` 与 `export type` 明确标记只存在于类型空间的依赖，并可安全从 JavaScript 输出移除。
4. 本课只证明相对路径 ES module 与类型导入，不把 package resolution 或条件导出提前带入基础课。

## 4. 最小临时 fixture

| 课程 | positive 必证 | negative 必证 |
| --- | --- | --- |
| 联合与字面量 | literal 状态、判别联合和穷尽分支可编译 | 非法 literal 产生 `TS2322` |
| 类型收窄 | `typeof`、`in`、`instanceof`、判别字段和 predicate 可编译 | 未收窄访问成员产生 `TS2339` |
| type 与 interface | alias union、interface extends 与声明合并可编译 | 同名 type alias 产生 `TS2300` |
| 模块 | 多文件 `import type`/`export type` 可编译 | 导入未导出成员产生 `TS2459` |

临时 runner 继续使用 T1-1 冻结的隔离配置，只断言正例 exit 0、负例非零与必要诊断码。模块 fixture
的入口可以引用同一临时目录中的其他文件，所有输入和 runner 均写入 `/tmp`，编译输出保持关闭；验证
后删除整个 `mktemp` 目录。

## 5. 结论

四课核心语义在宿主 6.0.3 与官方 7.0.2 范围内没有需要分叉教学的变化。T1-2 可以复用现有 catalog、
课程模板和临时验证方式；只在模块正负例的临时目录中增加多文件输入，不创建第二套 registry、持久化
测试 runner 或构建流程。
