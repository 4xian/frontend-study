## 3. 类型系统与推导

### 3.1 核心公共事实

1. TypeScript 是静态类型检查器：在运行前依据值的形状和可用操作报告潜在错误；合法 JavaScript 也
   可能被类型检查器拒绝。
2. 类型注解在 emit 时擦除，类型系统不会依据推导结果改变 JavaScript 的运行时行为，也不会提供额外的
   TypeScript 运行时库。
3. 推导发生在变量和成员初始化、默认参数、函数返回类型等位置；contextual typing 还能从表达式所在
   位置反向提供类型。
4. 局部初始化值通常不需要重复注解，但脱离上下文的函数参数可能退化为 implicit `any`；`strict` 下由
   `noImplicitAny` 报错。
5. `tsc` 可以在有类型错误时仍 emit；类型门禁必须读取诊断与非零结果，或显式使用 `--noEmit` /
   `noEmitOnError`。

事实依据：固定版
[New Programmer](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/get-started/TS%20for%20the%20New%20Programmer.md)、
[Basics](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Basics.md)
和
[Type Inference](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/reference/Type%20Inference.md)。

### 3.2 高价值易错候选

#### 1. 把类型注解或断言当成运行时校验

- **触发条件**：把 JSON、网络响应或 DOM 查找结果直接断言为期望类型。
- **原因**：断言只改变检查器看到的类型，emit 后不存在；`JSON.parse` 还可能传播 `any`。
- **后果**：编译通过，但错误形状在运行时触发 `TypeError`。
- **错误示例**：以下代码通过类型检查，但 `name` 实际为数字。

```ts
const raw = '{"name": 1}'
const user = JSON.parse(raw) as { name: string }

user.name.toUpperCase()
```

- **正确示例**：先把外部值停在 `unknown`，运行时核验后再使用。

```ts
const raw = '{"name": "Ada"}'
const value: unknown = JSON.parse(raw)

if (
  typeof value === 'object' &&
  value !== null &&
  'name' in value &&
  typeof value.name === 'string'
) {
  value.name.toUpperCase()
}
```

适用边界：当前课只建立“类型不验证外部数据”的边界；完整 narrowing 和 type predicate 留到基础第 6
课。该错误本质是“无诊断漏洞”，不能伪造诊断码。

#### 2. 看到 JavaScript 产物就认为类型检查通过

- **触发条件**：只检查输出文件是否存在，不检查编译诊断。
- **原因**：默认 emit 与类型门禁是两个维度。
- **后果**：带已知类型错误的 JavaScript 仍可能进入发布产物。
- **错误示例**：两版都报告 `TS2322`，默认仍可产生 JavaScript。

```ts
const count: number = 'not a number'
void count
```

- **正确做法**：教学负例用 `--noEmit`；需要构建门禁时使用 `noEmitOnError`，并始终断言必要诊断码和
  非零结果。

适用边界：`noEmitOnError` 是构建策略，不是类型系统会改变运行时的证据。

#### 3. 把推导理解成“变量永远保持初始字面量”

- **触发条件**：由数字初始化可变变量，之后写入字符串。
- **原因**：`let count = 1` 推导为可继续写入的 `number`，不是任意类型容器。
- **后果**：错误赋值产生 `TS2322`。

```ts
let count = 1
count = 'one' // TS2322
```

```ts
let count = 1
count += 1
```

适用边界：literal widening 和 union 设计在后续课程展开；本课只证明“没有注解不等于没有类型”。

#### 4. 以为所有匿名函数参数都能自动推导

- **触发条件**：函数表达式没有目标函数类型，也没有参数注解。
- **原因**：contextual typing 依赖调用参数、赋值目标等上下文；独立函数没有可反推合同。
- **后果**：`strict` 下产生 `TS7006`，关闭严格模式时则静默成为 `any`。

```ts
const handler = (event) => event.type // TS7006
```

```ts
const handler: (event: { type: string }) => string = (event) => event.type
```

适用边界：上下文只能来自已知静态位置，不会读取未来运行值。

### 3.3 官方事实 → 课程推导 → 适用边界

| 官方事实 | 课程推导 | 适用边界 |
| --- | --- | --- |
| 静态检查发生在运行前，类型随后擦除 | 首屏图示必须分开 source、check、emit、runtime | 不把 TS 描述成运行时验证器 |
| 初始化、返回值和上下文可参与推导 | 局部值优先利用推导，外部边界和公共函数写清合同 | 不推广“永远不要写注解”的绝对规则 |
| 默认可在错误下 emit | 负例断言诊断与非零结果，发布门禁显式禁止错误 emit | 输出文件存在不等于检查通过 |

### 3.4 版本判断与 fixture 建议

- **版本判断**：四项公共事实和选定的 `TS2322`、`TS7006` 在 6.0.3/7.0.2 实测一致。
- **正例**：变量和返回值推导、数组回调 contextual typing，双版本均要求 exit 0。
- **负例**：保留一个不匹配赋值 `TS2322` 和一个独立参数 implicit `any` `TS7006`。
- **配对证据**：另用仓库外 emit 目录证明“默认产生 JS / `noEmitOnError` 不产生 JS”；不要把该检查
  混入浏览器 Demo。

## 4. 常用类型

### 4.1 核心公共事实

1. 常用 primitive 类型写作小写 `string`、`number`、`boolean`；大写 `String`、`Number`、`Boolean`
   是很少应出现在应用合同中的 wrapper 类型。JavaScript 没有独立 `int` / `float` 类型。
2. `T[]` 与 `Array<T>` 描述同一种数组；`[T]` 是恰好一位的 tuple，不是数组的另一种拼法。
3. `any` 会关闭后续检查；`unknown` 可以接收任意值，但使用前必须收窄。
4. `null` 和 `undefined` 是否必须显式处理取决于 `strictNullChecks`；课程与 fixture 固定开启严格检查。
5. `never` 表示不会被观察到的值或永不返回的路径，不等于普通无返回值函数的 `void`。
6. 后缀 `!` 和其他断言一样只改变类型，不会在运行时检查值是否缺失。

事实依据：固定版
[Everyday Types](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Everyday%20Types.md)、
[More on Functions](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/More%20on%20Functions.md)
和
[Type Compatibility](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/reference/Type%20Compatibility.md)。

### 4.2 高价值易错候选

#### 1. 使用大写 wrapper 类型代替 primitive

- **触发条件**：用 `new String()` 创建值，或把 `String` 写进数据合同。
- **原因**：primitive 与 wrapper object 是不同类型和值类别。
- **后果**：赋给 `string` 产生 `TS2322`，并让 API 合同混入不必要的对象包装。

```ts
const label: string = new String('Ada') // TS2322
```

```ts
const label: string = 'Ada'
```

适用边界：`String(value)` 作为运行时转换函数可以使用；错误的是把 wrapper object 当作常规 primitive。

#### 2. 用 `any` 接收不可信输入

- **触发条件**：外部值声明为 `any` 后直接访问属性或调用方法。
- **原因**：`any` 明确退出类型检查，后续结果继续传播为 `any`。
- **后果**：拼写错误和不存在的方法无诊断，失败推迟到运行时。

```ts
declare const payload: any
payload.profile.name.toUpperCase()
```

```ts
declare const payload: unknown
payload.profile // TS18046
```

正确路线是把边界值保留为 `unknown`，经运行时检查后再读取。适用边界：`unknown` 只是阻止未经证明的
使用，本身不会自动校验数据。

#### 3. 在严格空值检查下直接使用可能缺失的值

- **触发条件**：直接使用 `find` 返回值、可空输入或可选属性。
- **原因**：`undefined` / `null` 是类型合同的一部分。
- **后果**：可能访问缺失值；最小 `find` 例产生 `TS18048`。

```ts
const found = ['Ada'].find((name) => name === 'Grace')
found.toUpperCase() // TS18048
```

```ts
const found = ['Ada'].find((name) => name === 'Grace')
const normalized = found?.toUpperCase()
```

适用边界：关闭 `strictNullChecks` 会改变诊断，不能用宽松配置生成本课证据。

#### 4. 把 `never` 当成“没有返回值”

- **触发条件**：给正常结束或只做副作用的函数标注 `never`，或向 `never` 变量赋值。
- **原因**：`never` 表示该值不可被观察；普通无返回值函数的结果是 `void`。
- **后果**：普通值赋给 `never` 产生 `TS2322`，可正常结束的 `never` 函数也会被拒绝。

```ts
const impossible: never = 'value' // TS2322
```

```ts
// 抛出错误并终止当前路径
function fail(message: string): never {
  throw new Error(message)
}
```

适用边界：用 `never` 做判别联合穷尽检查在后续 union/narrowing 课程展开。

#### 5. 用后缀 `!` 掩盖真实缺失值

- **触发条件**：未建立不为空证据就写 `value!`。
- **原因**：non-null assertion 被擦除，不产生运行时检查。
- **后果**：编译无诊断，实际为 `undefined` 时仍会崩溃。

```ts
declare const value: number | undefined
value!.toFixed()
```

正确做法是 guard、默认值或修正上游合同。该候选属于无诊断漏洞，只能做 paired fixture，不能固定一个
不存在的错误码。

### 4.3 官方事实 → 课程推导 → 适用边界

| 官方事实 | 课程推导 | 适用边界 |
| --- | --- | --- |
| `any` 不检查，`unknown` 要求先证明 | 外部输入默认停在 `unknown`，避免 `any` 扩散 | `unknown` 不等于已验证数据 |
| `strictNullChecks` 使缺失值显式 | 缺失值在类型中建模，并在消费点 guard/default | 宽松配置下同一源码可能无诊断 |
| `never` 不可被观察，`void` 表示忽略结果 | 分开教授不可能路径和普通副作用函数 | 穷尽状态机留给后课 |
| `T[]` 与 `[T]` 含义不同 | 本课只提示差异，下一课用长度/位置约束证明 | 不在本课提前展开 tuple API 设计 |

### 4.4 版本判断与 fixture 建议

- **版本判断**：选定的 primitive、`any`/`unknown`、nullish 和 `never` 行为以及
  `TS2322`、`TS18046`、`TS18048` 在两版实测一致。
- **正例**：小写 primitive、`unknown` guard、可缺失值 guard/default、真正抛出的 `never` 函数。
- **负例**：wrapper → primitive `TS2322`、直接使用 `unknown` `TS18046`、直接使用可能缺失值
  `TS18048`、普通值 → `never` `TS2322`。
- **静默配对**：`any` 与后缀 `!` 必须另放能通过编译但暴露风险的 paired fixture；不能把“无诊断”误写成
  negative diagnostic。

## 5. 对象、数组与元组

### 5.1 核心公共事实

1. 对象类型按成员结构描述值；可选属性 `?` 表示属性可能不存在，`strictNullChecks` 下读取结果包含
   `undefined`。
2. `readonly` 只阻止通过当前类型位置重写属性，不改变运行时，不是深层不可变；可写 alias 仍可能改变
   同一个对象。
3. 新鲜对象字面量会做 excess property check；先存入无目标类型变量后再传递，检查行为可能不同，因此
   对象类型不是一般意义上的 exact object。
4. `ReadonlyArray<T>` / `readonly T[]` 可读但不能通过该引用修改；可变数组可以赋给只读视图，反向不行。
5. tuple 在类型层知道长度和每个位置的类型，运行时仍是数组；tuple 可以有 optional、rest 和 readonly
   元素。

事实依据：固定版
[Object Types](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Object%20Types.md)
以及结构兼容边界的
[Type Compatibility](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/reference/Type%20Compatibility.md)。

### 5.2 高价值易错候选

#### 1. 直接读取可选属性

- **触发条件**：读取 `factor?: number` 后立即调用 number 方法。
- **原因**：属性不存在时 JavaScript 返回 `undefined`。
- **后果**：严格模式产生 `TS18048`，放过后可能运行时失败。

```ts
// 格式化可选缩放系数
function scale(options: { factor?: number }) {
  return options.factor.toFixed(2) // TS18048
}
```

```ts
// 使用默认值格式化缩放系数
function scale({ factor = 1 }: { factor?: number }) {
  return factor.toFixed(2)
}
```

适用边界：`exactOptionalPropertyTypes` 还会影响“缺省”和“显式写 `undefined`”的赋值语义，本课 fixture
显式固定该开关，不在此候选混讲。

#### 2. 把 `readonly` 当成深冻结或运行时冻结

- **触发条件**：只给外层属性加 `readonly`，却期望内部对象也完全不可变。
- **原因**：readonly property 只阻止属性槽重新赋值；内部值和可写 alias 仍可变化。
- **后果**：重写外层产生 `TS2540`，但内部更新可能合法且在运行时可观察。

```ts
interface Box {
  readonly value: { count: number }
}

// 尝试替换只读属性
function replace(box: Box) {
  box.value = { count: 1 } // TS2540
}
```

```ts
interface Box {
  readonly value: { count: number }
}

// 更新只读属性所引用对象的内部值
function increment(box: Box) {
  box.value.count += 1
}
```

若合同要求更深的只读视图，应逐层表达 readonly；即使如此也不等于 `Object.freeze` 的运行时保证。

#### 3. 把 excess property check 当成永久的 exact-object 检查

- **触发条件**：新鲜字面量把 `color` 拼成 `colour`，或把对象先存入无目标类型变量再传递。
- **原因**：新鲜字面量受特殊检查；普通变量主要按结构兼容检查。
- **后果**：直接调用在两版产生 `TS2561`，间接变量在有共同属性时却可能通过，拼写错误由此漏出。

```ts
interface Options {
  width: number
  color?: string
}

// 接收配置对象
declare function configure(options: Options): void

configure({ width: 100, colour: 'red' }) // TS2561
```

```ts
interface Options {
  width: number
  color?: string
}

const options: Options = { width: 100, color: 'red' }
```

正确路线是修正字段或在创建处保留目标类型；只有合同确实允许任意额外键时才加入 index signature，不能
用 assertion 掩盖拼写错误。

#### 4. 混淆可变长数组和固定位置 tuple

- **触发条件**：把 `[number]` 当成 `number[]` 的另一种写法，或读取 tuple 长度之外的位置。
- **原因**：tuple 编码位置和长度，普通数组只编码元素类型。
- **后果**：越界读取固定为 `TS2493`。

```ts
const pair: [string, number] = ['Ada', 1]
pair[2] // TS2493
```

```ts
const pair: [string, number] = ['Ada', 1]
const [name, rank] = pair

void name
void rank
```

适用边界：位置含义不直观时，官方文档也建议考虑用具名属性对象代替 tuple。

#### 5. 把 readonly array/tuple 交给承诺会修改的接口

- **触发条件**：把 `readonly T[]` 赋给 `T[]`，或把 `as const` tuple 传给可变 tuple 参数。
- **原因**：可变接收方可能写入，无法保护调用方的只读承诺。
- **后果**：readonly array 反向赋值固定为 `TS4104`；readonly tuple 调用在 6.0.3 为 `TS2345`，
  7.0.2 为 `TS4104`。

```ts
const readonlyNames: readonly string[] = ['Ada']
const mutableNames: string[] = readonlyNames // TS4104
```

```ts
// 计算只读坐标到原点的距离
declare function distance(point: readonly [number, number]): number

const point = [3, 4] as const
distance(point)
```

适用边界：只读消费 API 应接收 readonly；确需修改时先复制，再把复制品声明为可变值。

### 5.3 官方事实 → 课程推导 → 适用边界

| 官方事实 | 课程推导 | 适用边界 |
| --- | --- | --- |
| 可选属性读取可能是 `undefined` | 在消费点使用 guard、默认值或修正上游合同 | 不把 `?` 当成“该值总存在但可不写” |
| `readonly` 是浅层编译期约束 | 用它表达只读视图和 API 意图 | 不承诺深层或运行时不可变 |
| fresh literal 才有更强额外属性检查 | 在对象创建处保留目标类型，优先修正真实拼写错误 | 对象类型不是通用 exact-object validator |
| readonly array 单向可赋，tuple 固定位置 | 不修改的输入优先接收 readonly；固定位置协议才用 tuple | 语义不清晰时优先具名对象 |

### 5.4 版本判断与 fixture 建议

- **版本判断**：可选属性、浅 readonly、excess property、数组/tuple 公共语义一致；唯一实测诊断差异是
  readonly tuple → mutable tuple 的 `TS2345`（6.0.3）/ `TS4104`（7.0.2）。
- **正例**：可选属性默认值、正确对象字段、浅 readonly 的合法内部读取、mutable → readonly array、
  readonly tuple 参数，双版本 exit 0。
- **共同负例**：`TS2561`、`TS18048`、`TS2540`、readonly array 的 `TS4104`、tuple 越界
  `TS2493`。
- **版本化负例**：readonly tuple → mutable tuple 单独存放并维护双版本 expectation，禁止硬写成一个共享
  诊断码。
- **静默配对**：readonly alias 和“对象先存变量后绕过 excess check”应作为编译通过的边界证明，不得
  误标为负诊断。

## 6. 函数

### 6.1 核心公共事实

1. function type expression 使用 `(parameter: Type) => ReturnType` 描述调用合同；参数名是语法的一部分。
2. 可选参数表示调用方可以省略或传 `undefined`；callback 类型中的可选参数表示实现者确实可以少传该
   参数，不是“使用方可选择少声明一个形参”。
3. JavaScript 会忽略额外实参，因此较少参数的函数可以代替较多参数的 callback；不需要把 callback 的
   后续参数标成可选来允许这种写法。
4. rest 参数类型是 array/tuple；普通数组 spread 不能证明固定参数个数，tuple 可以。
5. overload implementation signature 对调用方不可见，并且必须兼容全部 overload；参数数量和返回类型
   相同时，官方建议优先用 union parameter。
6. contextual `() => void` 可以接收实际会返回值的函数，但调用合同会忽略该值；显式声明为 `void` 的
   function declaration 则不能返回具体值。

事实依据：固定版
[More on Functions](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/More%20on%20Functions.md)
和函数兼容边界的
[Type Compatibility](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/reference/Type%20Compatibility.md)。

### 6.2 高价值易错候选

#### 1. 把总会传入的 callback 参数写成可选

- **触发条件**：实现始终传 index，却把 callback 合同写成 `index?: number`。
- **原因**：`?` 授权实现者省略该实参，因此使用方必须处理 `undefined`。
- **后果**：直接使用 index 产生 `TS18048`。

```ts
// 遍历数值并按需省略索引
declare function forEach(
  values: number[],
  callback: (value: number, index?: number) => void,
): void

forEach([1, 2], (_value, index) => index.toFixed()) // TS18048
```

```ts
// 遍历数值并始终传入索引
declare function forEach(
  values: number[],
  callback: (value: number, index: number) => void,
): void

forEach([1, 2], (value) => void value)
```

适用边界：只有实现真的可能省略该参数时才写 `?`。

#### 2. 把 implementation signature 当成可调用 overload

- **触发条件**：只写一个 overload，再用更宽的实现签名，随后按实现签名调用。
- **原因**：实现签名只用于检查函数体，对外不可见。
- **后果**：没有对应 overload 的调用产生 `TS2554`；实现与 overload 不兼容时产生 `TS2394`。

```ts
// 解析字符串
function parse(value: string): void
function parse() {}

parse() // TS2554
```

```ts
// 解析字符串或数字
function parse(value: string): void
function parse(value: number): void
function parse(value: string | number) {
  void value
}
```

适用边界：对外有几种真实调用形态，就必须有对应 overload；实现签名不计入公开调用数。

#### 3. 同参数数量和返回类型仍滥用 overload

- **触发条件**：分别为 string 和 array 写两个同形 overload，再传入两者的 union。
- **原因**：调用必须解析到单个 overload，union 实参不能“同时匹配两个”。
- **后果**：产生 `TS2769`；两版的详细候选文案不同。

```ts
// 返回字符串或数组的长度
declare function lengthOf(value: string): number
declare function lengthOf(value: unknown[]): number

const value = Math.random() > 0.5 ? 'Ada' : [1]
lengthOf(value) // TS2769
```

```ts
// 返回字符串或数组的长度
function lengthOf(value: string | unknown[]) {
  return value.length
}
```

适用边界：不同参数数量或返回值与输入强关联时仍可能需要 overload；本课不把 union 建议绝对化。

#### 4. 把普通数组 spread 给定长参数

- **触发条件**：数组字面量被推导为可变长 `number[]` 后 spread 到两个固定参数。
- **原因**：数组长度不受类型保证，调用方不能证明恰好两个值。
- **后果**：产生 `TS2556`。

```ts
const argumentsList = [8, 5]
Math.atan2(...argumentsList) // TS2556
```

```ts
const argumentsList = [8, 5] as const
Math.atan2(...argumentsList)
```

适用边界：目标本身是 rest parameter 时可以接收变长数组，不应套用定长 tuple 规则。

#### 5. 把 `void` 简化成“实现绝不能返回值”

- **触发条件**：看到 callback 合同 `() => void`，误以为实现返回值必然报错，或继续使用被忽略的结果。
- **原因**：contextual void 允许实际函数返回任意值，但调用合同把结果视为 `void`。
- **后果**：回调可以合法返回值；把调用结果赋给 number 则产生 `TS2322`。

```ts
const effect: () => void = () => 42
const result: number = effect() // TS2322
```

```ts
const collected: number[] = []
const effect: (value: number) => void = (value) => collected.push(value)

effect(1)
```

适用边界：显式 `function effect(): void { return 42 }` 是另一条规则，会被拒绝；课程必须把 contextual
assignability 与显式函数返回注解分开。

### 6.3 官方事实 → 课程推导 → 适用边界

| 官方事实 | 课程推导 | 适用边界 |
| --- | --- | --- |
| callback 的 `?` 表示实现可以省略参数 | callback 合同描述调用者会怎么调用，不描述使用方想写几个形参 | 实现确会省略时才标 optional |
| implementation signature 对外不可见 | overload 列出全部公开调用形态，并用宽实现承接 | 宽实现本身不是额外 overload |
| 同形 overload 常可改成 union | 参数数与返回类型相同时优先一个 union 参数 | 输入输出关联复杂时重新评估 |
| contextual void 忽略返回值 | 允许 `forEach((x) => target.push(x))`，但禁止依赖返回值 | 不等同显式 `(): void` 可返回具体值 |

### 6.4 版本判断与 fixture 建议

- **版本判断**：选定的函数合同语义和 `TS18048`、`TS2554`、`TS2769`、`TS2556`、`TS2322`
  在两版实测一致；`TS2769` 的详细文案不同。
- **正例**：required callback index、union parameter、readonly tuple spread、contextual void callback，双版本
  exit 0。
- **负例**：optional callback index `TS18048`、不可见 implementation 调用 `TS2554`、union 实参调用
  overload `TS2769`、普通数组 spread `TS2556`、读取 contextual void 结果 `TS2322`。
- **可选独立负例**：只有课程正文确实讲到实现兼容性时才增加 `TS2394`；不要为了堆诊断扩大 fixture。
- **文案约束**：只断言诊断码和对应源码标记，不锁 `TS2769` 的逐个 overload 文案。

## 7. T1-1 临时 fixture 冻结建议

### 7.1 最小目录与断言

每课仍是一组临时 fixture；一组内可有一个 positive 文件和若干只触发一个独立失败模式的 negative
文件，临时 runner 只写一个参数化检查，不为每个文件复制验证逻辑。

```text
/tmp/vue3-study-typescript-t1-1/<lesson>/positive/
/tmp/vue3-study-typescript-t1-1/<lesson>/negative/
```

建议为本批建立独立、不可继承宿主配置的最小 tsconfig：

| 配置 | 冻结值 | 理由 |
| --- | --- | --- |
| `strict` | `true` | 使 implicit any 和 nullish 诊断确定 |
| `target` | `ES2022` | 两版共同支持，避免依赖默认 target 变化 |
| `module` | `ESNext` | 固定解析入口；本批源码不依赖模块输出 |
| `lib` | `['ES2022']` | 排除 DOM 与宿主声明对基础诊断的干扰 |
| `types` | `[]` | 不自动加载工作区 `@types` |
| `noEmit` | `true` | 正/负类型 fixture 均不污染仓库 |
| `exactOptionalPropertyTypes` | `false` | T1-1 只验证可选属性读取，不混入赋值差异 |
| `noUncheckedIndexedAccess` | `false` | T1-1 不把普通数组索引检查混入 tuple 事实 |
| `stableTypeOrdering` | `true` | 满足官方 6→7 兼容声明；7.0 不提供关闭路径 |

| 课程 | positive 必证 | negative 必证 | 不进入共享 expectation |
| --- | --- | --- | --- |
| 类型系统与推导 | 推导与 contextual typing exit 0 | `TS2322`、`TS7006` | 默认 emit 证据单独写临时目录 |
| 常用类型 | primitive、unknown/null guard、never throw exit 0 | `TS2322`、`TS18046`、`TS18048` | `any`、`!` 的无诊断漏洞 |
| 对象、数组与元组 | optional default、readonly input、tuple exit 0 | `TS2561`、`TS18048`、`TS2540`、`TS4104`、`TS2493` | readonly tuple 的双版本诊断分支 |
| 函数 | required callback、union、tuple spread、void callback exit 0 | `TS18048`、`TS2554`、`TS2769`、`TS2556`、`TS2322` | `TS2769` 完整文案 |

### 7.2 断言规则

1. positive 只断言 exit 0 和零 diagnostics；不依赖 emit 文件。
2. negative 断言非零和必要诊断码；不固定 `1` 或 `2` 这类具体退出值。
3. 一个 negative 文件尽量只保留一个错误源，避免前一条错误改变后一条推导。
4. 对共享诊断码要求 6.0.3/7.0.2 都出现；readonly tuple 使用版本化 expectation。
5. 不锁完整英文文案、绝对路径、行列号或诊断排序。
6. `any`、断言、non-null assertion、readonly alias、contextual void 等无诊断行为使用 paired fixture；
   需要运行观察时只在仓库外临时输出执行最小 JavaScript。
7. 浏览器最多承担函数回调运行顺序，不得证明推导、tuple、overload、擦除或诊断。

## 8. TypeScript 7.0.2 与本地 6.0.3 边界

官方 7.0 发布文说明，7.0 以兼容 6.0 类型检查和 CLI 为目标；6.0 代码需启用
`stableTypeOrdering`，且不能依赖 `ignoreDeprecations`。同时 7.0 采用 6.0 的新默认值，并把部分已废弃
配置升级为 hard error。因此本批的“无语义差异”只适用于本文明确列出的普通 `.ts` 最小源码和显式配置，
不能外推到整个项目。

以下 7.0 差异不进入四课正文：

- 原生 Go 编译器、并行 checker/builder 和 watch 实现。
- 7.0 没有旧 programmatic Compiler API。
- template literal type 的 Unicode code-point 推导变化。
- JSDoc 语法收紧。
- deprecated 配置移除、默认 `module`、`target`、`types`、`rootDir` 等迁移问题。

这些内容分别属于 T2/T3、工具链或迁移 Reference。T1-1 只保留一句版本边界，不能借此扩课。
