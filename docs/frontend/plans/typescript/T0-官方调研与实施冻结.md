## 1. 结论与停止边界

TypeScript 当前官方稳定版冻结为 `7.0.2`，发布日期为 2026-07-08。语言、CLI、标准库与官方测试固定到
`microsoft/typescript-go` 的 `typescript/v7.0.2` tag，完整 commit 为
`2bd066d87f5bafd315be9f40889d0a60b9e58e0b`；官网内容固定到
`microsoft/TypeScript-Website` 的
`c8170c35bda4811c9516cbb69c39241ae4beb6d9` commit。

本地宿主实际安装 TypeScript `6.0.3`，低于官方稳定版。TypeScript 7.0 已迁移到原生编译器，且没有
旧 JavaScript Compiler API；Vue、Volar 等嵌入式工具链仍需 TypeScript 6.0。T0 不升级依赖。后续正文的
语言事实以 `7.0.2` 为准，宿主临时编译验证暂以本地 `6.0.3` 为基线；涉及 7.0 差异时，必须使用
仓库外、固定版本的临时 fixture 单独验证并明确标注结果，不能把两条基线混为一谈。

T0 冻结 24 课：T1 基础 8 课、T2 中级 8 课、T3 高级 8 课。Reference 冻结为 200 个稳定映射键，另有
deprecated、experimental、nightly、历史发布说明、标准库声明和工具接口观察范围。详细计算见
[`TypeScript官方覆盖矩阵.md`](../../coverage-matrices/TypeScript官方覆盖矩阵.md)。

T0 完成时必须先停止，未经用户确认不得开始 T1。用户已确认冻结范围并授权连续实施；后续仍须逐批完成
调研、实现、门禁、浏览器验证、复审与状态登记，批内不得提前发布下一批内容。

### 3.3 状态边界

- `stable`：`7.0.2` 语言、CLI、稳定 Handbook/Reference、LSP language server、版本化 ES5 至 ES2025
  声明和稳定 DOM/WebWorker 声明。
- `deprecated/removed`：`Advanced Types` 旧页；7.0 不再支持的配置和值；只保留迁移说明，不计稳定分母。
- `experimental/legacy`：`experimentalDecorators`、`emitDecoratorMetadata`、legacy decorator 声明，以及
  7.0 的 `--checkers`、`--builders`。现代 Stage-3 decorators 与 legacy 路线必须分开。
- `nightly`：`typescript@next`、7.1 API 草案、`lib.esnext.*`。Beta、RC 和历史
  `@typescript/native-preview` 均不作为稳定入口。
- `restricted`：7.0 没有 programmatic Compiler API。旧 Compiler API、Language Service API、插件 API
  只适用于 6.0 兼容线；7.0 使用新的 LSP language server，不能互换签名。

## 4. 官方范围与双向差集

覆盖矩阵以 Website commit 的路径作为官方键，以 `7.0.2` CLI、发布说明和源码声明纠正状态：

```text
officialStable = pinnedWebsiteKeys - navigation - deprecated - experimental - unsupported
siteCovered = referenceIndex.officialKey
missing = officialStable - siteCovered
extra = siteCovered - officialStable
targetMissing = availableTargets - realEntriesAndAnchors
```

每次 TA 批次必须把四个差集打印为结构化列表；只有 `missing=[]`、`extra=[]`、`targetMissing=[]`，并且
所有非稳定键都有状态，才能关闭稳定覆盖。官方网页数量、Reference 文件数量和站内 entry 数量是不同
维度，禁止互相替代。

冻结分母为 200 个稳定映射键：Handbook v2 16、General Reference 12、Utility Types 22、Declaration
Files 15、Modules Reference 5、Project Config 6、TSConfig 124。Release Notes 48 页、标准库 108 个
`.d.ts` 文件、19 个 7.0 CLI-only 参数和四类旧工具 interface 分开观察，不并入 200。完整键集、URL 和
计算式见覆盖矩阵。

## 5. 课程路线冻结

### 5.1 T1 基础：入口与终点

起点是不要求 TypeScript 经验、但已具备变量、函数、对象和 ES module 基础的学习者；终点是能够用
类型推导、收窄、对象/函数模型和模块组织一个小型 TypeScript 文件集，并读懂编译诊断。

每批先使用 `mktemp -d` 创建独立目录，验证 runner、编译输入和输出都位于该目录。fixture 不写仓库
`dist/`、`build/`，负例不加入应用 `tsconfig`。每个 fixture 只断言 exit code、关键诊断码或稳定输出
片段，结束后删除整个目录并确认无残留。

## 8. 临时反馈环、浏览器验证与 Gate T

后续每批只建立最少临时检查：一个 schema/template interface、一个 catalog 顺序/索引检查、一个代表
fixture runner 检查；只有新出现的独立失败模式才增加验证。负编译 fixture 必须先证明失败，再以同一
命令验证预期诊断；所有资产位于 `/tmp` 并在批次结束前删除，不能把一次 focused green 写成模块 Gate
关闭。

浏览器验证复用用户现有服务，不启动重复实例。每批只走一个代表课程和一个代表 Reference；GT-1 才统一
覆盖课程/Reference 总览、搜索、关联、前后篇、刷新深链、390px、键盘、reduced motion 和 200% 文本。

写入 `/tmp`，不能在仓库保留配置或结果文件。

Gate T 必须同时满足：24/24 课程、200/200 稳定 Reference 键、观察范围全登记、所有 available target
真实存在、Demo 同源、临时 fixture 确定且无仓库残留、按需加载无回归、最少质量命令通过、代表性
浏览器路径通过、Standards/Spec 均为 `PASS / 0 finding`。

## 9. 风险与明确延期

1. **双版本风险**：本地 6.0.3 与官方 7.0.2 跨越编译器实现迁移。T0 不决定升级；升级必须另立批次，
   先验证 Vue/Volar、Vite 和所有自定义工具兼容性。
2. **官网滞后**：Website 快照没有 7.0 Release Notes，TSConfig 库存含旧字段；Reference 必须依赖双向
   差集，不能只抄导航。
3. **API 缺口**：7.0 没有 programmatic API，Compiler API/Language Service/插件正文延期到 7.1 稳定
   API 发布并重新调研之后。
4. **标准库体量**：108 个声明文件是源码观察范围，不机械转为 108 篇文章；DOM/JSX 只围绕 TypeScript
   interface 和配置边界主题合并。
5. **诊断稳定性**：负例优先锁诊断码和最小语义，不锁整段易变文案；6.0/7.0 差异必须并列标记。
6. **运行时错觉**：类型擦除、编译失败、声明生成、模块解析和 build graph 永远不由浏览器卡片冒充。

明确延期：依赖升级、7.1 API、完整 Compiler API、custom transformer、全量 DOM/standard lib 条目、nightly
特性、legacy decorator 课程、React/Vite，以及任何后端内容。
