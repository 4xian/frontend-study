## 3. 冻结事实与边界

### 3.1 模板字面量类型

1. 模板字面量类型使用 JavaScript 模板字符串的形状，但处在类型位置；具体 literal 会拼接为新的
   string literal，插值为 union 时会产生所有组合的 cross product
   （[Template Literal Types](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Type%20Manipulation/Template%20Literal%20Types.md)）。
2. 模板字面量可以把对象键联合变成字符串协议，例如 ``${string & keyof Type}Changed``，从而拒绝
   错误事件名；通过泛型捕获前缀后，可用 `Type[Key]` 将回调参数恢复为原属性类型
   （[String Unions in Types](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Type%20Manipulation/Template%20Literal%20Types.md#string-unions-in-types)、[Inference with Template Literals](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Type%20Manipulation/Template%20Literal%20Types.md#inference-with-template-literals)）。
3. `Uppercase`、`Lowercase`、`Capitalize` 和 `Uncapitalize` 是编译器内建 intrinsic types，不从标准
   `.d.ts` 导入；7.0.2 checker 仍按字符映射实现它们
   （[Intrinsic String Manipulation Types](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Type%20Manipulation/Template%20Literal%20Types.md#intrinsic-string-manipulation-types)、[7.0.2 checker](https://github.com/microsoft/typescript-go/blob/typescript/v7.0.2/internal/checker/checker.go#L28999-L29012)）。
4. 大型字符串联合官方建议预先生成；本课只覆盖有限协议、单层组合、intrinsic 和与映射类型的
   `as` 重映射，不进入递归字符串解析、性能工程或运行期事件系统
   （[Template Literal Types](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Type%20Manipulation/Template%20Literal%20Types.md)）。

### 3.2 类与结构兼容

1. `implements` 只检查类是否可被当作接口使用，不改变类本身的类型推导，也不把接口参数类型注入
   类体；缺少接口成员会产生诊断
   （[`implements` Clauses](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Classes.md#implements-clauses)、[Cautions](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Classes.md#cautions)）。
2. `extends` 建立 JavaScript 的实际继承关系；派生类拥有基类成员并必须满足基类合同。没有显式继承
   时，类实例仍可按公共成员结构互相兼容
   （[`extends` Clauses](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Classes.md#extends-clauses)、[Relationships Between Classes](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Classes.md#relationships-between-classes)）。
3. 结构类型比较类的 instance side；static members 和 constructors 不影响类实例兼容。private 或
   protected 成员则必须来自同一声明类或继承层级，否则即使公共形状相同也不能赋值
   （[Classes](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/reference/Type%20Compatibility.md#classes)、[Private and protected members in classes](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/reference/Type%20Compatibility.md#private-and-protected-members-in-classes)）。
4. `public` 是默认可见性，`protected` 只在声明类和子类可见，TypeScript 的 `private`/`protected` 只
   在类型检查时强制；本课冻结 `implements`、继承、instance structural compatibility 与可见性来源，
   浏览器 Demo 只展示构造器与 `instanceof` 的运行身份，不展开 decorators、mixins、abstract
   constructor 或运行期 `#private` 性能与安全模型
   （[Member Visibility](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Classes.md#member-visibility)、[Caveats](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Classes.md#caveats)）。

### 3.3 模块解析与第三方类型

1. 模块解析由最终 host（例如 Node.js 或 bundler）定义，TypeScript 必须用 `module` 与
   `moduleResolution` 模拟该 host 的输出模块和查找规则；不存在脱离 host 的单一“正确”解析算法
   （[Module resolution is host-defined](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/modules-reference/Theory.md#module-resolution-is-host-defined)）。
2. `node16`/`nodenext` 反映 Node 的 ESM 与 CommonJS 双算法；`bundler` 支持 `package.json` 的
   `imports`/`exports`，同时允许 bundler 常见的无扩展名相对导入。`classic` 不应在现代项目使用
   （[moduleResolution option](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/tsconfig-reference/copy/en/options/moduleResolution.md)、[bundler](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/modules-reference/Reference.md#bundler)）。
3. 解析到库时，`.d.ts`/`.d.mts` 等声明文件提供 JavaScript 的类型描述，编译器会优先寻找 TypeScript
   或声明文件；裸包查找先尝试包自身的 types，再按目录向上尝试 `node_modules/@types`
   （[The role of declaration files](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/modules-reference/Theory.md#the-role-of-declaration-files)、[node_modules package lookups](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/modules-reference/Reference.md#node_modules-package-lookups)、[DefinitelyTyped / `@types`](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Type%20Declarations.md#definitelytyped--types)）。
4. 在支持的模式中，`package.json` `exports` 控制允许的入口和子路径，并可用 `types` 条件指向声明；
   没有生效的 `exports` 时，包入口字段按 `types`、`typings`、`main` 顺序尝试，并对运行时扩展名做
   TypeScript extension substitution
   （[package.json `exports`](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/modules-reference/Reference.md#packagejson-exports)、[package.json `main` and `types`](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/modules-reference/Reference.md#packagejson-main-and-types)、[File extension substitution](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/modules-reference/Reference.md#file-extension-substitution)）。
5. `traceResolution` 是布尔诊断选项，会打印每个处理文件的解析过程；本批 CLI 固定为
   `tsc --project <临时目录>/tsconfig.json --traceResolution --pretty false`，不把源文件参数与
   `--project` 混用，也不锁定完整英文日志、探测顺序、绝对路径或 package ID。临时 runner 先归一化
   `/tmp` 与 macOS `/private/tmp` 根，再只断言说明符、解析模式和最终 `.d.ts` 相对路径
   （[Trace Resolution option](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/tsconfig-reference/copy/en/options/traceResolution.md)、[7.0.2 `traceResolution` declaration](https://github.com/microsoft/typescript-go/blob/typescript/v7.0.2/internal/tsoptions/commandlineoption.go#L81-L85)）。

### 3.4 `unknown`、`never` 与错误处理

1. `unknown` 可表示任意值，但在收窄前不能读取属性、调用或当作具体类型使用；它适合承接
   `JSON.parse` 和外部错误等不可信值
   （[`unknown`](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/More%20on%20Functions.md#unknown)）。
2. `useUnknownInCatchVariables` 让 `catch` 变量默认为 `unknown`，并随 `strict` 默认开启；处理前应使用
   `instanceof Error` 或其他真实运行时检查。7.0.2 的选项声明仍将它标记为 strict flag，默认描述为
   “true unless strict is false”
   （[Use Unknown In Catch Variables](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/tsconfig-reference/copy/en/options/useUnknownInCatchVariables.md)、[7.0.2 option declaration](https://github.com/microsoft/typescript-go/blob/typescript/v7.0.2/internal/tsoptions/commandlineoption.go#L615-L623)）。
3. `never` 表示收窄后不应存在的状态；它可赋给每种类型，但除自身外没有类型可赋给它。把默认分支
   的判别联合赋给 `never`，在新增未处理成员时会暴露穷尽性错误
   （[The `never` type](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Narrowing.md#the-never-type)、[Exhaustiveness checking](https://github.com/microsoft/TypeScript-Website/blob/c8170c35bda4811c9516cbb69c39241ae4beb6d9/packages/documentation/copy/en/handbook-v2/Narrowing.md#exhaustiveness-checking)）。
4. 本课只冻结不可信错误值的收窄、穷尽检查和最小 `Result` 风格合同；不把 `catch` 运行输出冒充类型
   诊断，不展开自定义 error hierarchy、异步边界或 T3 的复杂 `infer`/类型设计。本课运行 Demo 只
   展示 Error 与非 Error 的消息归一化。

## 4. 最小临时 fixture

| 课程 | positive 必证 | negative 必证 |
| --- | --- | --- |
| 模板字面量类型 | 有限键联合生成 `EventName`，`Capitalize` 与 mapped `as` 生成 getter 键 | `on('firstName')` 不符合 ``${'firstName' \| 'age'}Changed``，产生 `TS2345` |
| 类与结构兼容 | `implements`、`extends`、子类访问 `protected`，以及相同公共形状的类实例赋值 | 两个无继承关系的类各自声明同名 `private`，赋值产生 `TS2322` |
| 模块解析与第三方类型 | `Bundler` 项目从 `exports.types` 解析包声明，并从无 bundled types 的包回退到 `node_modules/@types` | 访问只导出根入口的包子路径，产生 `TS2307` |
| `unknown`、`never` 与错误处理 | `catch` 中先用 `instanceof Error` 收窄，判别联合默认分支赋给 `never` 可编译 | 未收窄的 `catch` 属性访问产生 `TS18046`；新增未处理联合成员赋给 `never` 产生 `TS2322` |

单文件课程使用本地 `6.0.3` 的隔离调用
`tsc --ignoreConfig --noEmit --strict --skipLibCheck --target ES2022 --module ESNext --moduleResolution bundler --pretty false <fixture>`；六个单文件结果为 positive exit 0，negative 非零且分别得到
`TS2345`、`TS2322`、`TS18046`/`TS2322`。模块临时 fixture 使用两个本地伪 npm 包、一个 `exports.types`
声明和一个 `@types` 回退声明；`tsc --project <config> --pretty false` 的 positive exit 0，访问未导出
子路径的 negative 得到 `TS2307`。

复验时，所有源码、伪 npm 包、配置、runner 和输出都创建在 `/tmp` 的同一 `mktemp` 目录中。模块
positive 的 `--traceResolution` 在相同临时路径连续运行两次，原始输出一致；归一化临时根后
只冻结以下摘要，不锁定完整日志：

```text
typed-package   Bundler -> node_modules/typed-package/types/index.d.ts
legacy-package  Bundler -> node_modules/@types/legacy-package/index.d.ts
```

验证完成后删除整个临时目录，不在仓库保留 fixture、runner 或输出。
