> 版本：v1.0

> 状态：计划已整理，尚未授权实施
> 当前基线：Java 基础 18 课、中级 17 课、高级 16 课，共 51 课

> 当前课程表与逐课实施入口已迁移到
> [`spring-boot-web-curriculum-plan.md`](./spring-boot-web-curriculum-plan.md)。本文件保留为开发范围、
> 内容深度和质量要求的背景规范，不再作为新版课程顺序的权威来源。

## 1. 计划目标

在保留当前 Java 课程知识深度的基础上，把学习路线调整为真正适合零基础学习者的连续路径：

```text
Java 零基础
-> 可运行、可调试、可测试的 Java 程序
-> 第一个 Spring Boot Web API
-> 具备分层、校验、错误处理和测试的 Web 服务
-> 接入最小 MySQL 持久化与 Redis 缓存
-> 具备安全、集成、观测和部署能力的生产级 Web 服务
-> 数据库完整专项课程
-> Redis 完整专项课程
```

完成基础、中级和高级主线后，学习者应能独立开发、测试、保护、观测和部署 Spring Boot Web
服务。数据库与 Redis 在主线中只建立真实接入闭环；设计、优化、高可用和故障处理分别放入后续独立
专项课程。完成三个阶段不等于已经掌握数据库和 Redis 的全部能力。

## 3. 当前判断

当前 51 课已经具备较高的 Java 与 Spring 后端知识覆盖，但仍存在以下学习路径问题：

1. 单课普遍有零基础解释，但缺少从第一次运行到第一次完整 Web 服务的阶段性反馈链。
2. 基础阶段没有独立的调试、Javadoc 阅读和最小 JUnit 课程。
3. Spring Boot、依赖注入、MVC、校验、错误与测试已经覆盖，但缺少一门低负担的“第一个 Web API”
   桥接课。
4. 单课示例较完整，但缺少把多课能力组合起来的基础、中级和高级阶段项目。
5. SQL、MyBatis、事务、Redis、分片与 Spring Web 主线混在同一个 Core 路线中，初学者容易在尚未
   建立 Web 心智模型时进入数据专项细节。
6. 集成测试、API 文档、API 兼容演进、应用镜像、健康探针和优雅停机还没有形成独立课程闭环。
7. 高级阶段混合了通用必修与专项选修，不能继续把所有课程视为同等优先级。

本计划不推翻现有 51 课，也不因重新分层而删除已经完成的正文和 signoff。实施前先冻结迁移表、稳定
ID、URL 和模块边界；未完成新轨道前，不提前移除当前可访问课程。

## 4. 调整原则

### 4.1 零基础原则

1. 术语必须先解释再使用。
2. 一门课程不得依赖尚未出现的框架、配置、命令或工程约定。
3. 初次出现的命令必须说明执行目录、输入、预期输出和失败现象。
4. 初次出现的框架能力必须先给最小可运行示例，再解释内部机制。
5. Java 25 和当前稳定 Spring Boot 是现代主线；Java 8、Spring Boot 2.3 只作为隔离的 legacy 补充。
6. 基础阶段不引入 Spring；中级阶段不深入数据库和 Redis 原理；高级阶段不以分布式平台作为前置。

### 4.2 内容优先级

每门课最重要的两项内容是：

1. **知识点详解**：解释是什么、为什么需要、有什么作用、什么时候使用、如何使用和容易错在哪里。
2. **如何使用示例**：提供可运行代码、完整步骤、预期结果、失败示例和可重复验证。

课程数量、标题和理论广度不能替代这两项。不能通过增加更多概念列表来弥补缺少解释或示例的问题。

### 4.3 主线与专项边界

| 轨道 | 负责回答的问题 | 不在本轨道深入的内容 |
| --- | --- | --- |
| Java / Spring Boot Web 主线 | 如何开发、测试、保护、观测和部署一个 Web 服务 | 数据库优化、Redis 高可用、消息系统和平台治理 |
| 数据库专项 | 数据如何建模、持久化、迁移、并发控制、优化和恢复 | Redis 缓存与消息代理 |
| Redis 专项 | 缓存与分布式状态如何建模、一致化、扩展和排障 | 关系模型、SQL 优化和数据库事务实现 |

## 5. 统一单课模板与验收标准

所有新增或实质调整课程遵守
[Java 课程编写标准](./java-course-authoring-standard.md)，并额外执行以下内容 Gate。Java 学习课程的
格式与内容深度不得低于已确认的[变量与赋值示例](./java-course-content-sample.md)。

### 5.1 每个小知识点

每个可独立学习的小知识点使用一个三级标题，并至少包含：

1. **它是什么**：先用日常语言解释，再给准确术语。
2. **有什么作用**：说明解决的问题和缺少它的后果。
3. **什么时候使用**：说明适用场景、前置条件和不适用边界。
4. **怎么使用**：按真实执行顺序给出步骤。
5. **最小示例**：只引入当前知识点需要的代码或配置。
6. **运行结果**：展示输出、HTTP 响应、状态变化或编译结果。
7. **常见误区**：说明错误认识；完整错误代码放入“易错点”。

涉及语法、API、配置或命令时，不能只写文字定义。每个重要知识点至少有一个可独立理解的使用
示例；纯概念知识也必须提供可观察场景、对比表或调用流程。

### 5.2 从零跟着做

“从零跟着做”必须说明：

1. 使用的精确 Java、Spring Boot 和依赖版本；
2. 从哪个目录开始；
3. 需要创建哪些文件；
4. 每段代码放在哪里；
5. 使用什么命令启动或验证；
6. 预期看到什么输出、响应或状态；
7. 至少一个失败路径如何触发、定位和恢复；
8. 完成后如何清理临时环境。

### 5.3 示例要求

1. 示例必须围绕中性的任务管理服务，避免依赖真实业务背景。
2. 每个知识点先有独立最小示例，阶段项目不能代替单点示例。
3. 同一阶段的项目可以逐步累积，但每课必须声明本课新增的行为和前置 checkpoint。
4. Java 方法和构造器定义上方使用规范中文注释。
5. 成功示例必须给出预期结果；错误示例必须给出触发条件、错误现象、原因和正确写法。
6. Web 课程使用 curl、MockMvc 或真实 HTTP 请求验证，不能只证明应用成功启动。
7. 数据库桥接课必须验证真实写入、读取和回滚；Redis 桥接课必须验证命中、过期、失效和不可用回退。
8. 验证资产放入 `/tmp` 的 `mktemp` 目录，成功后删除，不在仓库保留测试文件或 fixture。

### 5.4 课程负担

| 阶段 | 建议单课时间 | 处理规则 |
| --- | ---: | --- |
| 基础 | 45～90 分钟 | 一个核心心智模型，避免同时解释现代和 legacy 两条主线 |
| 中级 | 90～150 分钟 | 一个框架边界加一个完整反馈环 |
| 高级 | 120～180 分钟 | 同时包含成功路径、失败路径和资源生命周期 |

预计超过 180 分钟的课程应优先拆分为主线和扩展，不能只延长预计时间。

基础阶段目标是让零基础学习者能够编写、运行、调试和测试一个完整 Java 程序，不使用 Spring、

### 6.2 基础阶段项目

“命令行任务管理器”只使用 JDK、Maven 和 JUnit，至少包含：

- 创建、完成、列出和按状态筛选任务；
- 使用类、枚举、集合和 Optional 建模；
- 保存到文本文件并重新加载；
- 对非法输入给出可解释异常；
- 使用断点定位一次错误状态；
- 使用最小 JUnit 测试验证新增、筛选和文件往返。

项目必须按 checkpoint 提供可运行快照，不能要求学习者一次输入完整项目。

## 7. 中级阶段目标路线

中级阶段目标是让学习者从 HTTP 和 JSON 开始，完成一个具备分层、校验、持久化、错误处理、测试和
接口文档的 Spring Boot REST 服务。

### 7.1 推荐顺序

| 顺序 | 课程 | 处置 |
| ---: | --- | --- |
| I-01 | Lambda、方法引用、Stream 与 Collectors | 保留 |
| I-02 | 标识符、相等性与稳定排序 | 从现有标识符课程拆出；分页移到 I-09 |
| I-03 | JSON、对象映射与外部数据合同 | 保留 |
| I-04 | HTTP、URI、请求响应与 URL 编码基础 | 保留 |
| I-05 | 第一个 Spring Boot Web API | 新增低负担桥接课 |
| I-06 | IoC、构造器注入与 Bean 生命周期 | 移到 Spring Boot 深入课之前 |
| I-07 | Spring Boot 启动、自动配置与配置建模 | 保留；I-05 只预览，不重复深入 |
| I-08 | Spring MVC、Servlet 与请求生命周期 | 保留 |
| I-09 | REST 资源、状态码、分页参数与幂等请求 | 由现有 HTTP、分页和幂等内容重组 |
| I-10 | Bean Validation、参数绑定与输入合同 | 保留 |
| I-11 | 分层架构、DTO、Service 与仓储接口 | 保留 |
| I-12 | Spring Boot、MySQL 与 MyBatis 最小持久化闭环 | 新增桥接课 |
| I-13 | 错误合同、Problem Details 与结构化日志 | 保留 |
| I-14 | JUnit、Mockito 与 Service 单元测试 | 调整现有测试课；基础 JUnit 不再重复 |
| I-15 | Controller 测试、MockMvc 与测试切片 | 新增 |
| I-16 | OpenAPI、接口文档与接口联调 | 新增 |
| I-17 | Lombok、可变模型与生成合同 | 保留；可标记扩展 |
| I-18 | 策略、模板方法、适配器与回调 | 保留 |
| I-19 | 领域值对象、树结构与对象映射 | 保留 |
| I-20 | 中级实战：任务管理 REST API | 新增阶段项目 |

### 7.2 MySQL / MyBatis 桥接边界

I-12 只建立 Spring Boot Web 服务的最小真实持久化闭环，必须讲解并示范：

- 数据库、表、行、列、主键和连接的基本含义；
- DataSource 配置和连接失败的可观察现象；
- 一张任务表和一个最小版本化 migration；
- Mapper 接口、参数绑定和最小 CRUD；
- Controller -> Service -> Repository/Mapper 的调用路径；
- 一个成功事务和一个回滚示例；
- 使用 curl 和最小自动化检查验证真实写入、读取、约束失败与回滚。

I-12 不深入 JOIN、复杂动态 SQL、索引、执行计划、隔离级别、锁、备份恢复和分库分表。这些属于数据库
专项课程。

### 7.3 中级阶段项目

“任务管理 REST API”在基础项目的领域语义上重建为 Spring Boot 服务，至少包含：

- 任务创建、查询、更新、完成和分页列表；
- JSON 请求响应、正确状态码和稳定错误合同；
- Bean Validation 与字段级错误；
- Controller、Service、Repository/Mapper 分层；
- MySQL 一张主表和版本化 migration；
- Service 单元测试、Controller MockMvc 测试；
- OpenAPI 文档与可重复 curl 验收。

本阶段不加入 Redis、安全认证、消息队列或微服务平台。

## 8. 高级阶段目标路线

高级阶段目标是让学习者把中级服务提升为具备并发边界、外部集成、安全、缓存、资源生命周期、观测和
部署合同的生产级 Spring Boot Web 服务。

### 8.1 通用必修顺序

| 顺序 | 课程 | 处置 |
| ---: | --- | --- |
| A-01 | 线程池、并发集合、锁与共享状态 | 保留 |
| A-02 | ThreadLocal、请求上下文传播与清理 | 保留 |
| A-03 | 事件、异步执行、调度与重试 | 保留 |
| A-04 | HTTP 客户端、超时、资源生命周期与集成韧性 | 保留 |
| A-05 | Spring Boot 集成测试、WireMock 与测试分层 | 新增；数据库容器测试留给数据库专项 |
| A-06 | API 版本演进、兼容性与契约测试 | 新增 |
| A-07 | 认证、授权、资源边界与 JWT | 保留并前移 |
| A-08 | 输入安全、过滤链、CORS 与 API 暴露边界 | 保留并前移 |
| A-09 | Spring Boot、Redis 与最小缓存闭环 | 新增桥接课 |
| A-10 | 文件上传、存储、下载与归档安全边界 | 保留 |
| A-11 | Actuator、日志、指标、Trace 与故障定位 | 扩展现有 JVM 可观测性课程 |
| A-12 | 应用镜像、自动化交付、健康探针与优雅停机 | 新增 |
| A-13 | 高级实战：可部署的生产级 Spring Boot Web 服务 | 新增阶段项目 |

### 8.2 Redis 桥接边界

A-09 只建立一个可验证的 Cache Aside 闭环，必须讲解并示范：

- Redis、key、value、TTL、缓存命中和缓存未命中的基本含义；
- Spring Data Redis 连接、序列化和 key 命名；
- 第一次请求读取 MySQL 并写入 Redis；
- 第二次请求命中 Redis；
- TTL 到期后重新加载；
- 更新数据库后主动失效缓存；
- Redis 暂时不可用时回退数据库，并记录可观察日志或指标；
- 用真实请求和自动化检查验证命中、过期、失效与回退。

A-09 不深入缓存穿透、击穿、雪崩、Lua、分布式锁、Streams、持久化、Sentinel 或 Cluster。这些属于
Redis 专项课程。

### 8.3 高级选修

以下现有课程保留，但不阻塞通用 Spring Boot Web 主线：

- 反射、Spring AOP 与横切合同；
- WebSocket 会话、广播、心跳与回收；可补 SSE 对比；
- 随机访问、压缩、图像与流式背压；
- 密码学 API、秘密管理、签名与许可证校验；
- 责任链、注册表、工厂与状态机；
- Legacy 隔离、javax/jakarta 与现代化迁移。

数据库分片课程移入数据库专项候选；当前缓存与一致性课程移入 Redis 专项候选。独立专项未完成前，
现有页面保持可访问，不提前删除 loader、正文或 signoff。

### 8.4 高级阶段项目

高级项目在中级项目基础上增加：

- JWT 认证、资源级授权和输入安全；
- 一个带超时、重试预算和 WireMock 失败场景的外部 HTTP 集成；
- Redis 查询缓存、TTL、更新失效和不可用回退；
- 文件上传下载的大小、类型、文件名和资源关闭边界；
- request correlation、结构化日志、Actuator、指标和最小 trace；
- API 兼容性和契约测试；
- 非 root 应用镜像、配置外置、startup/readiness/liveness；
- 流量摘除、在途请求完成或超时退出的优雅停机验证。

完成项目后，学习者应能够解释每个组件的 owner、输入、输出、失败路径和验证证据，不能只展示一次
成功请求。

## 9. 数据库独立专项课程方向

数据库专项在 Spring Boot Web 三阶段主线关闭后单独冻结课程数、版本和实现范围。建议顺序为：

1. 关系模型、表、主键、外键与约束；
2. DDL、DML、查询、聚合、JOIN 与子查询；
3. JDBC、DataSource 与连接池；
4. Spring Boot 数据源与 MyBatis 基础；
5. Mapper XML、动态 SQL 与结果映射；
6. Flyway/Liquibase、schema history 与兼容发布；
7. 事务、隔离级别、锁与死锁；
8. 索引、EXPLAIN、分页与查询优化；
9. Testcontainers 与真实数据库集成测试；
10. 数据变更、备份、恢复和故障演练；

## 13. 单批实施流程

每门新增或实质调整课程按以下顺序闭环：
