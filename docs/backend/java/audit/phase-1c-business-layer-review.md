现代课程应先用接口表达稳定的业务合同，再用单个实现类承担业务编排；需要依赖时优先使用显式
构造器注入。项目中 155 个文件的字段注入只作为迁移证据，不作为推荐示例。`@RequiredArgsConstructor`

注入。

不能机械复制“接口 + Impl”命名，而应先确认接口是否真正形成多个实现、调用边界或测试替换价值；
单一实现且没有边界价值时不为了形式额外创建接口。

## 6. 事务与代理边界

| 信号                                  | 数量 |
| ------------------------------------- | ---: |
| 含 `@Transactional` 的文件            |   96 |
| 方法级 `@Transactional`               |  463 |
| 含 `@Async` 的文件/方法               |  1/1 |
| 同文件出现事务与 HTTP、I/O 或并发信号 |   63 |

本批所有 `@Transactional` 都作用于方法。注解出现不等于任意调用都启用事务：Spring 代理必须实际
拦截到符合条件的调用，类内自调用不会自动跨越代理边界。`@Async` 同样依赖代理调用，并且需要
明确执行器、异常观测、上下文传播和关闭策略。

63 个 `transaction-side-effect-mix` 只表示同一文件同时存在事务和 HTTP、I/O 或并发信号，不证明
它们一定处于同一方法或同一事务。Phase 2 选择代表性调用链时必须继续核对方法级边界，避免数据库
事务包住不可回滚的远程副作用、文件写入或长时间等待。

设计。

没有把每次构造都直接判定为资源泄漏。`HmBurnService` 还直接创建 `CloseableHttpClient`，后续示例
应统一配置连接池、连接/读取超时、复用和关闭生命周期。

## 10. 后续课程约束

1. 先讲现代 Java 接口、类、构造器注入和清晰服务边界，再补充项目的字段注入与旧兼容写法。
2. 事务课程必须同时覆盖代理调用、自调用、回滚规则、事务传播，以及外部副作用不随数据库回滚。
3. 异步与并发课程必须使用受管理执行器，并覆盖容量、拒绝、异常、上下文和关闭。
4. I/O 与 HTTP 示例必须使用结构化资源管理、明确超时和可观测错误，不复制手工资源生命周期。
5. Servlet request/response、MultipartFile 和登录上下文先在 Web 适配层转换，业务接口使用明确 DTO
   或值对象。
6. 只从超大类中抽取最小、去敏、纠正后的场景，不复制完整业务编排。
7. 硬编码秘密、字段注入、Service Locator、直接线程和字符串池锁只能作为迁移反例。
