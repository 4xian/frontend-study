## 2. 复核方法

1. 先运行全量只读检查，确认 Phase 1A、Phase 1B 和前八批仍绑定同一冻结快照。
2. 从冻结库存独立领取 257 个文件，逐个核对 SHA-256、LOC、声明、字段、公开方法、注解和使用边。
3. 对 101 个显式职责文件建立固定映射；其余 156 个文件必须同时满足“位于枚举目录、只有一个
   顶层类型、顶层类型为 enum”，才允许归入 `code-label-enum`。
4. 完整复核 6 个枚举目录特殊文件，并按类别复核密码学、TLS、反序列化、反射、并发、I/O、进程、
   HTTP、SQL 黑名单和认证数据等风险证据。
5. 把 257 条候选写入 6 个 `reviewing` JSONL 分片；人工签核绑定候选分片 SHA-256 后，才生成
   `reviewed` 完成态。
6. 独立 validator 不导入生成器或职责目录，重新从库存区间和当前源码复算范围、职责、角色、信号、
   风险行号、使用次数、职责内容语义哈希、签核绑定和累计状态。

敏感风险采用两条独立证据路径：生成器按人工确认的字段赋值和日志调用登记候选；validator 从
Phase 1B 字段声明、当前源码字面量和去除字符串后的日志标识符重新推导。两者不共享风险正则，避免
同一条窄规则同时漏掉 `GenAuthorization`、`JzRSAUtils` 或 `StzxUtil` 的证据。

风险项 `CC-0001..CC-0378` 是 Phase 2 的归一化输入，不是 378 个已经定性的独立缺陷。同一文件中
一类风险可以绑定多行证据；候选数按“文件和类别”计数，不按命中行数计数。

## 5. 枚举、常量与共享状态

162 个枚举目录文件中，156 个是普通代码枚举，另外 6 个分别是 JSON 标记基类、拖拽坐标模型、枚举
合同、JSON 值对象、常量类和反编译视频配置单例。不能因为目录名包含 `enums` 就统一教授为 enum。

126 个普通或嵌套枚举存在非 final 实例字段，6 个枚举还公开 setter，76 个文件的查找方法返回
`null`。现代示例应把枚举状态在构造时固定为 `private final`；查找失败根据合同选择明确异常、
`Optional` 或受控 `UNKNOWN`，不能把运行期可变枚举当作推荐写法。

7 个常量文件中既有真正不可变的协议值，也有内嵌密码材料和大型全局运行态注册表。
`JzglConstant` 不能作为“常量类”示例；它应进入进程内共享状态、并发可见性、清理和测试复位的
纠错材料。`TsAiRuntimeCache` 同样是并发运行态缓存，不是普通常量。

## 6. 标准库、I/O 与资源所有权

84 个 util 文件横跨字符串、日期、标识、反射、线程池、HTTP、SOAP、文档、图片、二维码、文件、
压缩、外部进程和模型推理。后续课程必须先建立语言与标准库前置，再进入这些组合能力：

- 枚举、集合、不可变数据、空值合同和异常；
- `Path`、`Files`、流、显式字符集和 try-with-resources；
- Executor 的队列、拒绝、取消、关闭和上下文传播；
- HTTP 客户端连接池、超时、响应关闭、重试、取消和幂等；
- 反射目标限制、类型合同、缓存边界和失败诊断；
- 文档、图片、压缩包和响应体的输入大小及内存上限。

`CommonUtil` 聚合了大量不相关职责，并包含无界压缩展开和 Java 原生反序列化候选；它只用于拆分
职责和输入边界的纠错案例。旧 `File` API、平台默认字符集和整份载荷入内存只作为 legacy 补充，
现代示例优先使用 NIO、显式 `StandardCharsets` 和有界流式处理。

## 7. 密码学、网络与认证边界

本批确认了 RSA、SM2、SM3、AES、3DES、摘要、HMAC、JWT 和请求签名等旧集成能力，也确认了 8 个
文件的内嵌密钥或密码材料、9 个文件的弱密码学兼容信号，以及 1 个信任全部证书和主机名的旧 TLS
客户端。它们证明项目存在兼容需求，不证明这些方案适合新系统。

现代课程必须先查询当前 JDK 和安全标准，使用受支持的算法、认证加密、受控密钥来源、证书链与
主机名校验；项目 Java 8 写法只放在 legacy 差异中。不得展示真实项目密钥、密码或完整敏感常量。

`SqlFilterUtil` 的关键字和正则黑名单只能作为项目兼容过滤证据，不能代替 SQL 参数绑定、上下文输出
编码、Bean Validation 和明确的请求边界。`LoginData`、`LoginRequest` 承载口令、派生值或令牌，
后续示例必须限制生命周期，禁止普通日志、缓存和无边界序列化。

4 个文件保留明确的反编译标记。反编译源码只用于解释项目现状；其命名、类型、单例、可变枚举和
生命周期都不能直接复制到现代推荐示例。

## 9. 后续课程约束

1. 基础阶段先讲常量、enum、不可变性、集合、异常和空值合同，再讲项目枚举与常量补充。
2. I/O 示例默认使用 `Path`、`Files`、try-with-resources、显式字符集和有界流式处理。
3. 密码学、TLS、JWT 和认证内容必须先按当前官方资料建立现代方案，项目旧协议只讲迁移边界。
4. 并发内容先讲 Executor 生命周期、任务取消和共享状态，再补充项目优先级线程池与静态缓存。
5. HTTP/SOAP/外部服务示例必须明确客户端、响应、超时、关闭、重试、取消和幂等所有权。
6. 反射优先替换为类型化接口；确需反射时限定目标、缓存和异常语义。
7. SQL 安全以参数绑定和上下文编码为基础，不教授关键词黑名单作为主要防线。
8. 认证模型、配置和日志示例必须去敏，禁止项目密钥、口令、令牌和内网地址进入课程。
9. 正式知识点开始前按来源规范查询当前 JDK、Spring、Servlet、HTTP 客户端和安全标准的官方资料，
   再补充项目 Java 8 / Spring Boot 2.3.12 差异。
